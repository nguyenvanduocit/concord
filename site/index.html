Parallel coding agents, one repo, code that still fits together.

concord is a command-line tool your agents run while they work on the same project. It gives each function to one agent at a time, tells callers when a contract changes, and lands the combined work once the agents checked it against what each one said done means. Any folder works as it is: no setup, no git needed, and your git is never touched.

The problem is stale contracts, not merge conflicts

Agent A renames total to subtotal. Agent B makes it return a float. Agent C, at the same time, writes receipt() against the old total. A structural merge combines all three without a single conflict, and the result is broken:

Measured

On a scenario built to collide, every version-control setup tested landed broken code. The protocol concord implements landed it correctly. Each setup ran once, so these numbers show failure modes, not rates.

2/4tests pass after git + Mergiraf merges the three agents' work
0/3agents could even commit in one shared GitButler directory
4/4tests pass with the board and a check before landing, first run
30/30reviews rejected the float bug without running code
20/20reviews landed correct code when criteria were read against each agent's own change

Outside work points the same way: two agents splitting a pair of tasks succeed about 30% less often than one agent doing both, and wrong beliefs about the other's plan are the top cause (CooperBench). When one agent changes an interface another uses, the combined code failed in 97% of constructed runs (2609.25396). Single preprints, not replicated.

Your folder afterwards

A landed round arrives in your project folder like a pull, as plain uncommitted edits. Edits you made there before or during the round stay. concord never reads or writes .git: if you use git, you review and commit the round with it. Every landed round is one line in .concord/ledger.jsonl: who changed what, their criteria and contracts, and the reviewer's evidence.

$ git status --short     # your git, if you use one
 M cart.py
 M test_cart.py
$ tail -1 .concord/ledger.jsonl
{"agents":[{"agent":"agent-a","contracts":[{"id":"total#1","note":"subtotal(items)
-> int: sum of price * qty; CHANGED: renamed from total",…}],"criteria":["total is
renamed to subtotal with unchanged behavior; nothing calls total"],"head":"…"},…],
"at":…,"base":"…","landed":"…","reviews":[{"evidence":"a: no total() left; …",
"reviewer":"agent-c"}]}  # shortened with …

Install

From a checkout of the source. Building needs Rust 1.89 or newer; concord merges files with Mergiraf, which must be on your PATH.

$ cargo install --path .              # the concord binary
$ brew install mergiraf
$ cp -r skills/concord ~/.claude/skills/   # teaches agents the protocol

That is all the setup. Give each agent its task and tell it to follow the concord skill. Its first concord plan, run anywhere in the project, joins it and hands it a workspace of its own; when the last agent finishes, the round is reviewed and lands. Optionally, add "$HOME/.cargo/bin/concord" hook claude as a Claude Code PreToolUse hook on Edit|Write|MultiEdit|NotebookEdit, so sessions that edit the project without concord are told who is working.
