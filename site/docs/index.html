Getting started

concord is a command-line tool that lets several coding agents edit the same project at the same time and still land code that works together. Your agents run it; you hand them tasks.

Install

From a checkout of the source. Building needs Rust 1.89 or newer.

cargo install --path .

This installs the concord binary. concord merges files with Mergiraf, which must be on your PATH (brew install mergiraf). Nothing else: concord keeps its own files in a .concord/ folder in your project and needs no git, jj or any other version control.

Teach your agents the protocol

The repository ships an agent skill at skills/concord/. Copy that folder into ~/.claude/skills/ so Claude Code agents know the worker protocol. Copy it again after editing it.

Tell sessions that do not know yet

Optionally, add concord as a Claude Code PreToolUse hook on Edit|Write|MultiEdit|NotebookEdit:

"$HOME/.cargo/bin/concord" hook claude

When a session edits the main folder of a project whose board has agents, it gets one note per session saying who is working and how to join with concord plan. The hook never blocks an edit and stays silent everywhere else.

Run agents with no setup

Give each agent its task and tell it to follow the concord skill. Each agent's first command, run anywhere in the project, joins it:

$ concord plan total item_count -- "subtotal(ITEMS) == 25; nothing calls total any more"
JOINED agent-1
WORKSPACE agent-1 /work/shop-agent-1
PLANNED agent-1 modifies=['total'] uses=['item_count']
-> from now on work in /work/shop-agent-1: claim, edit, done, finish there

The agent moves into the workspace it was given and does everything else there. A workspace is a separate copy of the project, next to it, starting from your folder as it was when the first agent joined, uncommitted edits included. Your own folder is never an agent's workspace, so you and other sessions can keep editing it.

After -- the agent states what done means for its own change. When the last agent of the round finishes, concord combines everyone's work and asks the agents to review it against those criteria. Their approval lands the round in your folder as uncommitted edits. Nothing to run. See Landing.

Or set the team up yourself

An orchestrator can create the workspaces up front, from the project folder:

$ concord init agent-a agent-b agent-c
INIT agent-a agent-b agent-c
BASE 642280a23870 (/work/shop)
WORKSPACE agent-a /work/shop-agent-a
WORKSPACE agent-b /work/shop-agent-b
WORKSPACE agent-c /work/shop-agent-c

Dispatch one agent per workspace. Each brief holds the agent's name, its workspace path, its task, and "follow the concord skill (worker protocol)". Do not tell agents about each other's tasks; the board does that.

While they work, concord status shows who holds and waits on which function and who has finished. concord log shows the events.

The board serializes functions, not files. Give each shared non-code file (docs, changelog, config) to exactly one agent, or edit it yourself after the round lands.
