Landing

concord combines every finished agent's work and checks what needs no judgment. Then it hands the combined result to the team's own agents for review. Each agent stated at plan what done means; the round lands in your folder when the reviewers confirm it.

The last finisher reviews

The finish that leaves every agent finished, with nothing to re-check, combines the round and exits 12. This is agent-c's, from the cart scenario:

$ concord finish
FINISHED agent-c at fbc060aa2066: no unseen contract changes
ROUND complete: combining everyone's work for review
agent heads: eab5e0fc5148 f95b99fd3b82 fbc060aa2066  ->  tips to combine: fbc060aa2066
REVIEW fbc060aa2066 by agent-c
SELF-REVIEWED agent-c: no other agent's own session to hand its criteria to
REVIEW REQUIRED agent-c: check this round's combined work before it lands
COMBINED fbc060aa2066 checked out at /work/shop-concord-gate
  read it: concord show fbc060aa2066 [<file>], concord diff 642280a23870 fbc060aa2066
CHECK each agent's done-criteria against that agent's own work (concord diff 642280a23870 <head>):
  agent-a at f95b99fd3b82: total is renamed to subtotal with unchanged behavior; nothing calls total
  agent-b at eab5e0fc5148: subtotal(items, discount_pct=0) returns gross * (1 - discount_pct / 100);
                           subtotal(ITEMS, discount_pct=20) == 20
  agent-c at fbc060aa2066: receipt(items) returns "<count> items, total <total>";
                           receipt(ITEMS) == "3 items, total 25"
CHECK the combined result against every contract change of the round (is every caller adapted?):
  total#1 by agent-a: subtotal(items) -> int: sum of price * qty; CHANGED: renamed from total
  total#2 by agent-b: subtotal(items, discount_pct=0) -> float; CHANGED: now always float, format before printing
-> then: concord land "<evidence per criterion, file:line>"   (the round lands when every reviewer approved)
   or:   concord reject <agent> "<what is wrong>"   (nothing lands; the agent fixes it)
$ echo $?
12

Each criterion is read against that agent's own head: criteria describe one agent's change, and a later agent's declared change would make them fail against the combined code. The contracts are read against the combined result, where a stale caller shows. When an agent rewrote its criteria after starting, the first version is printed next to the current one (CRITERIA CHANGED).

The last finisher's own criteria go to another agent whose session concord can continue on this machine, most recently active first; concord resumes that session with the review (RESUMED). With none, as in this scripted run, the last finisher checks its own too, and the log says SELF-REVIEWED, so the weaker check stays visible.

Approve: lands like a pull

$ concord land "a: cart.py has no total(); b: cart.py:4-7 subtotal(ITEMS, 20) == 20; c: cart.py:15-17 receipt(ITEMS) == '3 items, total 25'"
APPROVED by agent-c
LANDED fbc060aa2066
REMOVED workspace agent-a
REMOVED workspace agent-b
REMOVED workspace agent-c
ROUND agent-a, agent-b, agent-c landed; still working: none

Once every reviewer approved, the combined result is merged into your project folder. Only paths the round changed are touched, so edits you made there before or during the round stay; a file both you and the round changed is merged by Mergiraf, and any conflict left is printed as CONFLICTS. The landed agents' workspaces and the review checkout are removed. Agents still working keep going and land in a later round, from the landed code.

concord never reads or writes .git. If you use git, the landed round shows up as uncommitted edits; review and commit it with git yourself.

The ledger

Each landing appends one line to .concord/ledger.jsonl: when, the base, the landed change, each agent with its head, criteria and contracts, and each reviewer's evidence. The ledger is the project's history; the change graph in .concord/objects holds the files.

Reject: back to the author

$ concord reject agent-b "subtotal returns gross, discount_pct ignored (cart.py:6)"

Nothing lands, and your folder stays exactly as it was. The agent workspaces stay; the review checkout is removed. concord resumes the author's own session in its workspace with the reason (claude --resume <id> -p … or codex exec resume <id> …), so the agent that wrote the code fixes it with its context and finishes again. Sessions come from the environment at plan; no flag. Agents on another machine, and subagents that share their parent's session, are never resumed: concord prints the reason to relay instead. The third rejection of one agent in a round stops with BLOCKED <agent>: rejected 3 times and the resume command, for a person to look.

What concord checks itself

  1. Lost work. A finished change with no work of its own fails the round: when work is lost, its code and its test vanish together.
  2. Combine. In a folder of its own (<project>-concord-gate), the tips among the finished heads are merged one at a time, every file both sides changed by Mergiraf. One combine at a time, under a lock.
  3. Conflicts. Any left over fail the round.

A failure prints FAIL the round cannot be combined: <reason> with exit 1 to every agent that finishes, until one finishes at a new head. Your project folder is never touched.

Why not tests

The tests are written by the same agents. An agent that misreads its task writes a test that agrees with it, and lost work takes its test with it. On the cart scenario, a reviewer that could not run code, reading each agent's criteria against that agent's own change, rejected the bugs the tests catch 30 of 30 times and landed correct code 20 of 20 times, over two models. A bug no criterion names was found only by chance, as with tests. Details are in Findings.
